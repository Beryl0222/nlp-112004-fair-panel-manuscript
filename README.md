# 暗标材料的语义匿名与复核交接

鸣坡市技术标送审文书包含正文章、表格录入稿、补遗、名录和秘书签字。原稿中的引用保留印刷锚点。材料均用于内部演练。评分记录引用实际已发卷及项目编号，秘书处的身份资料只有内部可读。

## 本地资料

全部为 UTF-8 编码的合成业务资料。`data/contract.json` 中的列类型带 `?` 时可以是 JSON null。每组记录的 `id` 在该组中唯一，跨组关系以字段说明和清单的 `links` 为准。文字字段保留来源原句，嵌套对象按表中现有格式记录。

- `data/portraits.json`。秘书保管的虚构投标方公开画像。facts 为当时公开信息的原话。
- `data/review-criteria.json`。技术评议依据的正式条目。要求匿名卷能保全影响比较的条件。
- `data/blocks.json`。编号为原稿标记。text 为正文、表格自然语言转录或签补遗。anchor 同稿内可唯一定位。
- `data/reviews.json`。秘书有原标注和候选改写，category 为推荐、讨论或批准。raw 对应原稿编号。
- `data/dispatch.json`。已发的匿名纸面交接，links 将评审页定位到原稿，审阅者只收到匿名材料。
- `data/scores.json`。现有评分事实，用于还原评委实际引用。

## 使用约定

正文使用印刷位置定位，匿名卷的页码是独立编号。秘书端评分索引通过当次匿名卷编号和页码定位，修改稿不能覆盖旧索引。表A 的读数范围本身是可评依据，不因机型专名自动算作公司身份。投标人画像所列是秘书可用的有限公开资料，缺项不等于该条属性被证实不存在。技术条件在两份卷上无法作同口径比较时，评分登记为待补材料，不记零分。

## 读取与检查

使用 Node.js 22.23.4，依赖仅用 Node.js 标准库。资料检查依次读入各组 JSON，检查列类型、组内编号及已登记的组间引用，并列出各组记录数。读取入口为 `tools/materials.mjs`，可单独读取一组记录，或读取整个已登记资料包。

```sh
npm run check-data
npm test
```

## 匿名检查与复核交接工具

入口为 `tools/cli.mjs`，依赖仍只用 Node.js 标准库。身份线索包括直接称呼（画像别名）和能与画像相互印证的经历组合；机型专名等例行设备指称与通用作业约束不计入身份。既说明投标者又支撑技术判断的段落，报告会给出原话、合起来能识别的其他几处、以及候选改写可能丢失的技术含义；秘书可批准等义改写、退回，或在隐去身份与保全必评依据无法两全时标明待补交，由主办方索取可以公平比较的材料。

```sh
npm run review -- b1            # 发卷前秘书检查（缺省遍历全部投标人）
npm run export -- b1 决定.json   # 组装评委卷；未处置段落或整卷复检不过则拒发
npm run addendum                # 补遗与在评可读内容合并检查（缺省 p04、p05）
npm run scores                  # 评分台账：按实际引用卷次追查
npm run ranking -- t2           # 宣布排序的闸门
npm run trace -- issue-A A.2    # 秘书端从匿名卷一处追到原文与遮改记录
```

评委卷只含匿名文字与卷内引用，安全闸（`assertReviewerSafe`）拦截内部编号、画像指称和批注；原文索引、遮改理由与批准记录留在秘书映射里。补遗若补全身份链，照发即暴露，须先改写；若已发出则收回受影响卷次、暂停相关评分提交。补遗替换技术依据（如量程）时，引用旧依据的评分转草稿待复评，同条目结论暂缓宣布，有独立依据的打分继续。旧评分只按实际引用的卷次追查，禁止归到新证据。`examples/decisions-b1.json` 是秘书决定的示例格式。
